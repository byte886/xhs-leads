# 小红书页面导航与登录硬性规则（R-6.53z8）

> 状态：**强制规则，后续所有开发/改码/测试必须先读本文**。
> 来源：用户 2026-11-06 拍板（原话见文末）。
> 适用范围：**凡是 xiaohongshu.com 的页面**——采集页、登录小窗、导入 Cookie 后打开的页、
> 壳窗内嵌页、登录态探测页，全部适用，无例外。
> 关联代码：`backend/src/browser_client.py`、`backend/src/mirror.py`、`backend/src/server.py`、
> `backend/src/shell_window.py`。

## 一、一句话规则

**URL 只允许打开两个地址：`https://www.xiaohongshu.com/login` 和浏览页 `/explore`（且浏览页要分情况）；
其余一切页面（搜索页、笔记详情、作者主页）只能靠页面内操作到达，操作方式只允许模拟鼠标/键盘或 JS 点击。
任何情况下都不许刷新（`reload`）。**

用户原话（2026-11-06）：
- 「点刷新或者通过 URL 进入某个页面，很容易被要求登录或者是风控，我已经试验过了。」
- 「除了 login 页面，其他所有的链接都不要通过 URL 进入，全部靠模拟鼠标或者键盘的方式，或者 JS 点击的方式。」
- 「你能够通过 URL 的页面只有 login 这一个页面。」
- 「已经能登录的状态，它自然通过 login 页面能进入 explore。严格意义上 explore 是可以直接 URL 输入的，但是要看情况。」
- 「在你已经能确保是登录状态的情况下，是可以进入浏览页面；但如果你不确定，为了更安全的方式，可以通过登录页面而间接进入浏览页面。」

## 二、URL 白名单（只有两个）

| 目标 | 允许 URL 进入？ | 条件 |
|---|---|---|
| `/login` | **允许，无条件** | 任何时候都可以直接打开登录页 |
| `/explore` | **有条件允许** | 仅「已确认登录态」时；见下节三种情况 |
| 搜索结果页 `/search_result?keyword=…` | **禁止** | 必须点搜索框输入关键词回车 |
| 笔记详情 `/explore/{id}` | **禁止** | 必须在结果页点卡片 |
| 作者主页 `/user/profile/{uid}` | **禁止** | 必须点作者头像/昵称 |
| 任何页面刷新 `reload()` | **禁止** | 全场景禁用（含空壳重试） |

## 三、浏览页（/explore）的三种情况

| 情况 | 判据 | 允许的动作 |
|---|---|---|
| **A 已确认登录** | `login_status` 返回 `logged_in=true`，且页面不是游客渲染态（无「输入手机号」浮层、无「登录探索更多内容」） | 可以直接 `goto /explore`；也可以仍走 login 间接进入 |
| **B 不确定** | 状态未知、判定滞后、页面可能是游客渲染、刚从别的账号导入 Cookie | **只许走 `/login`**，由登录页自己跳 explore；停在 login 就等人扫码，不强行去 explore |
| **C 主动保守** | 任何想更稳的时候（默认推荐） | 直接走 `/login` 间接进入，完全不使用 explore 的 URL |

判定实现：`_ensure_browse_page()` = 先在浏览页且非游客渲染 → 放行；否则 → `_open_login_page()`（一次性 `goto /login`，等平台自跳）。
游客渲染判定 `_page_needs_login()`：页面存在 `输入手机号` 的 input 或正文含「登录探索更多内容」→ 视为需要登录。

> 注意：**Cookie 在 ≠ 页面按登录态渲染**。实测出现过 web_session 存在、页面整页按游客渲染：
> 此时点搜索框只会弹登录浮层、回车不触发搜索（2026-11-06 已实测，`#search-input` 值写入成功但不跳转）。

## 四、页面操作方式（唯一允许的两种）

| 方式 | 用法 | 适用 |
|---|---|---|
| 模拟鼠标/键盘 | `page.mouse.click(x,y)`、`page.keyboard.type(kw, delay≈90)`、`page.keyboard.press("Enter")` | 搜索输入、点卡片、点按钮（**默认选它**，最接近真人） |
| JS 点击 | `el.click()` | 页内筛选/分页等按钮；拿不到坐标时 |
| JS 滚动 | `window.scrollTo(0, scrollHeight)` | 滚动加载（已沿用，不用滚轮事件） |

坐标一律**动态计算**（`getBoundingClientRect()` 取中心点），禁止硬编码像素。
节奏按防风控口径：点击与输入之间留 0.5–1s，逐字输入 `delay=80~120ms`。

## 五、遇到登录墙/风控时的标准处置

1. 页面命中 `/login`、`captcha`、`website-login` → 判定为登录墙（`_wall_by_url`）。
2. **直接打开 `/login`**（这是允许的 URL），把页面留给人工扫码/过验证。
3. 抛 `BrowserLoginRequiredError` 中止任务，前端提示「在采集窗完成验证后重试」。
4. 不空等、不重试、不刷新、不换 URL 试探。

## 七、禁止清单（看到就是 bug）

- ❌ `page.goto("…/search_result?keyword=…")`
- ❌ `page.goto("…/explore/{note_id}")`、`page.goto("…/user/profile/…")`
- ❌ `page.reload()` / 任何形式的刷新重试
- ❌ 用 `location.href = …` / `window.open(url)` 绕过
- ❌ 未确认登录态就 `goto /explore`
- ❌ 在游客渲染页面上继续采集（应先走 `/login`）
- ❌ 详情/作者/评论另开 `_load(url)` 直进（唯一例外是 `note_url()` 的用户自有链接）
