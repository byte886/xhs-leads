# 接口清单与合理性审计（z8o）

> 口径：以「界面真的调」为准，`api.ts` 里有函数定义不算有人用（上一轮按字符串出现判定，
> 把包装函数也算成调用方，导致漏判）。

## 一、结论先行

- 路由总数：**49**（删除 1 个零调用端点后）
- 真正零调用（界面、脚本、后端内部都不调）：**3 个** — `POST /api/collect_resume`、`GET /api/qrcode`、`POST /api/mirror/event`
- 界面不调但别处在调：`POST /api/auth/login_cancel`（壳窗守卫）、`POST /api/mirror/open`（测试脚本起引擎）
- 本轮修掉的 3 个问题：发布缺登录前置、诊断接口吐明文 Cookie、`refresh_cookie_from_chrome` 零调用

## 二、按用途分组（49）

### 登录（8）
| 接口 | 用途 |
|---|---|
| `GET /api/login_status` | 是否已登录（唯一权威） |
| `POST /api/auth/login_begin` | 点「重新登录」打开登录页 |
| `POST /api/auth/login_cancel` | 登录页点「✕」回 APP 时取消（**壳窗守卫调用**） |
| `GET /api/auth/login_begin_state` | 守卫轮询：有无待处理登录请求 |
| `POST /api/auth/import_cookies` | 扫码后把登录态注入引擎（系统内部） |
| `POST /api/auth/collapse_debug_windows` | 强制登录时收起右窗 |
| `GET /api/qrcode` | 登录引导（**零调用**） |
| `POST /api/mirror/open` | 打开调试/登录窗（测试脚本用） |

### 授权（2）
`GET /api/license_status` 查授权；`POST /api/license_activate` 激活。

### 采集（6）
`POST /api/collect_start` 开始；`GET /api/collect_progress` 看进度；`POST /api/collect_stop` 停；
`POST /api/collect_resume` 唤醒等待登录的任务（**零调用**，事件驱动已覆盖）；
`POST /api/collect_giveup` 放弃剩余保留已采；`POST /api/search` 一次性搜索（界面已不调）。

### 状态与事件（2）
`GET /api/status_now` 顶部状态条；`GET /api/events` SSE 变化通知。

### 数据（6）
`GET /api/notes` 笔记列表；`GET /api/authors` 按作者聚合；`POST /api/download_images` 打包 zip；
`POST /api/open_folder` Finder 定位；`GET /api/img` 图片预览；`POST /api/cleanup_images` 清无引用图片。

### 客户（3）
`POST /api/clients` 抓评论区用户；`GET /api/clients_list` 客户库明细；`GET /api/clients_agg` 客户页统计。

### 创作与发布（8）
`POST /api/clone` 克隆爆款；`POST /api/upload_image` 追加图片；`POST /api/save_draft` 存草稿；
`GET /api/drafts` 草稿列表；`POST /api/draft_delete` 删草稿；`POST /api/publish` 真发布；
`POST /api/publish_stats` 回抓发布数据；`GET /api/logs` 发布记录（**命名易误解为运行日志**）。

### AI（7）
`GET/POST /api/llm_config` 读写 AI 配置；`POST /api/llm_config/clear` 清空；`POST /api/llm_test` 测连通；
`GET/POST /api/persona` 读写人设；`POST /api/ai_generate` 生成文稿。

### 窗口与调试（4）
`GET/POST /api/app_config` 读写 APP 设置；`POST /api/mirror/window` 调试窗有头/无头；
`GET /api/mirror/screenshot` 取画面；`POST /api/mirror/event` 转发点击输入（**零调用**）。

### 内部诊断（1）
`GET /api/cookie_info` 只读 Cookie 摘要（值已掩码，无界面入口）。

### 页面（1）
`GET /` APP 界面。

## 三、本轮修复

| 问题 | 处理 |
|---|---|
| `POST /api/refresh_cookie_from_chrome` 零调用，且与 `login_status` 判定有效即 `risk.resolve` 完全重叠 | 删除端点，同步删除待办 M2 与三份文档的引用 |
| `POST /api/publish` 无登录前置：未登录点发布，跑到平台才失败 | 加 `_require_login_fast()`：只读 15s 缓存 + 风控状态，不连 Chrome。**没有**改成 async——发布内含 2–5s 拟人停顿，async 会阻塞整个事件循环 |
| `GET /api/cookie_info` 返回**完整明文**会话 Cookie | 改为掩码（前 3 + 后 3）；界面已无入口，排障只需要知道「哪条在、到没到期」 |

## 四、待决（本轮未动，需产品判断）

| 接口 | 现状 | 建议 |
|---|---|---|
| `POST /api/collect_resume` | 零调用。登录中断的恢复已由事件驱动自动完成 | 删。若保留就是"兜底按钮"，但界面上没有这个按钮 |
| `GET /api/qrcode` | 零调用。现在登录引导靠 SSE 事件 + 强制登录弹窗 | 删；除非要保留一个"手动要登录"的备口 |
| `POST /api/mirror/event` | 零调用。调试窗目前只做画面展示 | 删；删后调试窗变为只读，符合"看画面"的用途 |
| `GET /api/search` | `api.ts` 有函数、界面无调用；采集已走 `collect_start` | 删（前端函数 + 后端端点），除非有外部脚本依赖 |
