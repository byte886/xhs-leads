# 多专家角色迭代开发工作流 SOP v1.0

> 版本：v1.0（2026-11-03，R-6.38a）
> 取代：`开发对齐机制.md`（Phase-Gate 阶段会议，保留为历史记录）
> 衔接：README 提交前检查 → `QUALITY-REPORT-2026-11-03.md` → 本 SOP；`roles/*.prompt`（6 个旧 swarm 模板，未启用，由本 SOP 角色定义取代，不删除）。

## 一、目的与适用范围

把「一个人闷头改」升级为「多专家角色轮换/并行子智能体」的迭代机制：每个变更（R 批）经过 挑刺→建议→裁判→落地→验证 闭环，避免问题反复修反复出、老问题重现。适用于本仓所有文档/代码/测试变更；纯一次性问答不启用。

## 二、术语与角色

| 角色 | 职责 | 输出 |
|---|---|---|
| 挑刺者（Critic） | 只看不改，找问题；评审视角=Google 七看：Design / Functionality / Complexity / Tests / Naming / Comments / Style | 问题清单：位置+问题+证据（行号/路径） |
| 建议者（Advisor） | 对每个问题给 ≥2 个选项 + 利弊 + 推荐 | 建议清单（含推荐项） |
| 裁判者（Judge） | 裁定取舍 + 理由；重大方向取舍停下问用户；文档级可逆决策可自主裁定并留记录 | 裁定表（采纳/驳回/转用户） |
| 执行者（Doer） | 按裁定落地修改 | diff + commit |
| 验证者（Verifier） | 独立验证（不与执行者同一份上下文） | 验证报告 |

> 映射本仓执行方式：上述角色可由不同子智能体并行承担，或单智能体按节轮换；关键是「挑刺与落地分离」——落地者不替自己开脱。

## 三、前置条件

- 工作区干净或与本批文件互斥（文档线/代码线/测试线三线文件互斥）。
- 已知基线：pytest 数、commit/merge 门当前值、远端分支同步。
- 待改文件已 Read 现状（不凭记忆假设内容）。

## 四、流程步骤（七步）

1. **触发与目标声明**：写明本轮范围、文件互斥边界、验收出口。
2. **挑刺盘点**：挑刺者只读盘点，产出问题清单（位置+问题+证据）。
3. **建议**：建议者对每条给选项+利弊+推荐。
4. **裁判**：裁判者裁定；重大方向取舍（合并/删除/架构方向）停下问用户；文档级可逆决策自主裁定并记录。
5. **落地**：执行者按裁定改文件。
6. **验证出口**：验证者跑验收（见 §六）。
7. **提交与决策记录**：每批一个 commit（R-6.38x 开头），删除/收敛清单逐条进 message；mini-ADR 入库（见 §五）。

**触发点**：每轮 R 批开始、方向取舍前、删除/收敛决策前、质量门修复、上游工具更新、老问题重现。

## 五、输入与输出（决策记录 mini-ADR）

每条重要决策按 mini-ADR 格式留痕：

```
ADR-0001：主题
- 背景与证据：…
- 候选方案：A / B / C
- 裁定：…
- 理由：…
- 状态：已采纳 / 已驳回 / 转用户
- 落点 commit：<hash>
```

> 参考实践：ADR（archived decision records） https://adr.github.io/ ；Michael Nygard《Documenting Architecture Decisions》 https://cognitect.com/blog/2011/12/15/documenting-architecture-decisions ；MADR https://github.com/joelparkerhenderson/architecture-decision-record 。
> 评审话术：Conventional Comments 前缀（praise/nitpick/suggestion/question/thought/issue）https://conventionalcomments.org/ 。

## 六、质量标准与验收出口

一轮 R 批收尾必须同时满足：
- pytest 全量 ≥ 基线（当前 321）；
- commit 门 + merge 门全绿（`quality-check.sh --stage commit/merge`）；
- 文档引用核验：grep 0 断链；
- `bash -n` / `py_compile` / `vue-tsc` / `vitest`（按改动面）；
- git 干净，`pull --rebase` 后 push 成功；
- 决策记录（mini-ADR 或 commit message 清单）入库。
