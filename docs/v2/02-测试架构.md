# 测试架构 v2（测试唯一真相源）

> 替代关系：本文替代 `quality-gates/`、`scripts/ui_tests/README`、`ui-test-checklist`、`dev-test-batches` 作为测试口径。
> 总原则：**测试只为 AC 服务**。没有 AC 编号的测试不进门禁（可以写，但不作为交付证据）。

## 一、五层结构

| 层 | 名称 | 测什么 | 工具 | 目标占比 | 单次耗时 |
|---|---|---|---|---|---|
| T0 | unit | 纯函数、状态机、评分、分级、URL 白名单、配置解析 | pytest / vitest | 60% | < 15s |
| T1 | contract | 44 个路由的请求-响应契约、状态码、异常分支、字段必填 | pytest + TestClient | 20% | < 30s |
| T2 | engine | 引擎池、窗口、导航、注入、守卫（全部 mock，不碰真 Chrome） | pytest + fake_playwright | 10% | < 20s |
| T3 | redline | 源码级与运行时红线断言（禁 close/reload、goto 白名单、无硬编码路径、无代发） | pytest（读源码 + AST） | 5% | < 5s |
| T4 | ui | 真浏览器烟测 + 人工闸口 | Playwright（连 CDP 9223） | 5% | 3–10min |

**分工铁律**：T0–T3 必须完全离线可跑（无 Chrome、无网络、无登录态）；只有 T4 允许碰真环境。任何"为了跑通而 mock 掉业务判断"的测试，不算覆盖。

## 二、目录结构（新）

```
backend/tests/
  unit/          # T0：score/risk/intent/urls/config/jsonio/license/llm_service
  contract/      # T1：按域拆 aauth_ / coll_ / clone_ / pub_ / client_ / set_ / lic_
  engine/        # T2：engine_pool / shell_window / browser_client（fake_playwright）
  redline/       # T3：test_no_close_reload.py / test_goto_whitelist.py / test_no_hardcoded_path.py / test_no_autopublish.py
  fixtures/      # fake_playwright.py, seed_db.py, api_client.py
frontend/src/    # vitest co-located（沿用现状：*.test.ts 与源文件同目录）
scripts/ui/      # T4：只保留 3 个入口
  smoke_unlogged/  layout/  collect_lowfreq/
trace/
  AC-TRACE.yaml  # 机器生成，勿手改
  manual-gates.yaml  # 人工闸口登记（手写）
```

## 三、AC 与测试的绑定方式（机器可验）

1. 测试用标记声明归属：`@pytest.mark.ac("AC-AUTH-01")`；vitest 用 `// @ac AC-FRONT-01` 注释。
2. `scripts/trace.py` 做三件事：
   - 收集所有标记，生成 `trace/AC-TRACE.yaml`（AC → nodeid 列表）
   - 校验 01 文档里每条 AC 要么有标记、要么在 `manual-gates.yaml` 登记、要么标 `X`
   - 发现"孤儿测试"（无 AC 标记）与"裸 AC"（有 AC 无测试）都报非零退出
3. commit 门跑 `trace.py --check`；merge 门跑 `trace.py --strict`（裸 AC = 0）。

**为什么这样做**：你现在的三向矩阵是人手维护表格，实测已经要靠 ADR 打补丁。改成标记 + 生成，追溯就不再需要人维护。

## 四、断言纪律（从旧 UI 脚本血泪教训升级为强制规则）

| # | 规则 | 违反后果 |
|---|---|---|
| R1 | 禁止在 `evaluate` 内做 DOM `click()`（Vue `@click` 不响应合成事件） | 用例直接判失败（T3 扫描 UI 脚本源码） |
| R2 | 断言可见性用 `is_visible()`，禁止 `count() > 0` | 同上 |
| R3 | Tab 切换前必须等 onMounted 稳定（等待目标 hint 出现），点完再等 hint 变更 | 走查项，人工复核 |
| R4 | 每条用例至少一条真实 `assert`；无 assert 的脚本不允许进 `scripts/ui/` | T3 扫描 |
| R5 | SKIP 必须带理由码（`NO_DATA` / `NOT_LOGGED_IN` / `RATE_LIMIT`），且退出码 2 | run 脚本统计 |
| R6 | 断言值必须来自后端真实值或固定 fixture，禁止"看起来对"的近似 | code review |

## 五、门禁定义（替换旧六维）

**commit（≤60s，本地 pre-commit）**
1. T0 + T1 + T3 全绿
2. `trace.py --check` 通过（改 AC 必同提交带测试）
3. 禁出现：`page.close()` / `browser.close()` 于 engine/shell 相关函数体；`reload(` 全仓；`/Users/` 硬编码
4. `py_compile` + `vue-tsc --noEmit`

**merge（CI，≤10min）**
1. 以上全部
2. T2 全绿
3. T4 烟测：`smoke_unlogged`（冷启动页面集）+ `layout`（已登录，可缺省跳过并登记）
4. 变异测试：`score` / `risk` / `urls` / `intent` 四个纯逻辑模块 **存活变异体 = 0**
5. `trace.py --strict`：裸 AC = 0
6. 覆盖率：`server` ≥ 80%，`engine_pool` ≥ 60%（较旧 45% 提标），其余 ≥ 60%；`shell_window`/`browser_client` 不计入（由 T4 + 人工闸口守护，理由登记）

**nightly**
- 跑 `legacy/` 旧套件做对照，输出差异清单（重建期用，P2 完成后停）

## 六、人工闸口登记格式（`trace/manual-gates.yaml`）

```yaml
AC-AUTH-03:
  title: 扫码登录注入 id_token
  precondition: 未登录实例 + 手机小红书 App
  operator: 用户本人
  steps: [点「去登录」, 扫壳窗二维码, 等待 login_status=logged_in]
  evidence: docs/gates/2026-XX-XX-login.md
  last_run: 2026-11-07
```
规则：人工闸口必须写"看什么算通过"，不允许写"人工确认"四个字了事。

## 七、迁移步骤（P2 按域增量）

1. 打 tag 并把旧套件整体移入 `legacy/`（`git mv`，不删）
2. 先建 T3（红线）——零依赖、当天可绿，先锁住最贵的坑
3. 按域迁 T0/T1：每迁一个域，旧域测试在 `legacy/` 停跑，新域在 `tests/` 开跑；同时把 AC 标记补上
4. T2 最后迁（引擎依赖最多）
5. T4 只收 3 个入口，其余旧脚本一律归档不迁
6. 全部迁完后删 `legacy/` 的 nightly 任务，打 tag `v2-tests-cutover`

## 八、明确不做

- 不引入 Playwright Test Agents（planner/generator/healer）：与既有 UI 断言纪律冲突，healer 的"跳过"语义会掩盖真 bug。
- 不引入覆盖率补测工具（Qodo Cover 类）：覆盖率已由 AC 追溯 + 变异测试守，工具只补数字不补语义。
- 不做"AI 自动改测试让它通过"：失败必须由人或 triager 分类，不得自动修绿。
