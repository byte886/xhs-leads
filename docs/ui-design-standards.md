# UI 设计规范（XHS Leads）

> 目的：统一 XHS Leads 界面弹框、提示与表单的文案与视觉基线，避免每次改版各自发挥。
> 适用：登录提示弹框、确认弹框、表单错误提示、空状态、系统条等 B 端界面元素。
> 依据：Material Design Dialog 规范、IBM Carbon Design System Dialog 模式、NN/g / UX Writing 微文案原则、豆包官方 doubao-ui-design 技能（Phosphor 图标、四组数值方法）。

## 1. 弹框结构（三段式，不多不少）

任意弹框只有三层信息，按序排列：

| 层 | 内容 | 字数上限 | 示例 |
|---|---|---|---|
| 标题 | 一句说明"是什么" | ≤ 10 字 | 需要登录小红书 |
| 正文 | 一句说明"为什么 + 下一步"，面向用户 | ≤ 30 字 | 登录已失效，重新登录后才能继续采集 |
| 主操作 | 唯一的行动按钮 | ≤ 6 字 | 去登录 |

可选辅助行（一行小字，非必需）：
- 只放"怎么做"的补充，如「将跳转小红书官方登录页 · 扫码或手机号均可」
- **禁止**出现：负向强调（"此对话框不可关闭"）、技术术语（Cookie / 风控 / 引擎 / 会话）、多层说明。

## 2. 文案规范（UX Writing）

- **面向用户**：说用户能做的事，不说内部机制。`登录已失效` 而非 `账号被小红书风控拦截（Cookie 有效但需人工扫码/验证）`。
- **平静 + 建设性**：错误提示先说明现状，再给出下一步动作；不指责、不制造焦虑。
- **每个词都要有价值**：一屏只保留最少文字；能一行说清就不用两行。
- **术语一致性**：登录相关统一用「登录 / 登录状态 / 重新登录」；不混用「会话 / 凭证 / 认证」。

## 3. 视觉基线（B 端浅色）

| Token | 值 | 用途 |
|---|---|---|
| 品牌强调色 | `#ff2442` | 主操作按钮、图标底、可点击强调 |
| 标题字色 | `#222` | 弹框标题（17px / 600） |
| 正文字色 | `#444` | 弹框正文（14px / 1.6 行高） |
| 辅助字色 | `#999` | 底部辅助行（12px） |
| 弹框底色 | `#fff`，圆角 16px，阴影 `0 16px 48px rgba(0,0,0,.14)` | 内容卡片 |
| 遮罩 | `rgba(30,30,34,.35)` + `backdrop-filter: blur(3px)` | 遮罩层 |
| 间距 | 图标下 14 / 标题下 10 / 正文下 24 / 按钮下 14 | Material 24/20/8 的紧凑适配 |
| 图标 | Phosphor（MIT，`fill=currentColor`，一稿一种字重） | 禁止字母占位、emoji、手搓 path 之外的来源 |

## 4. 图标规范

- 一律用 Phosphor 图标库（doubao-ui-design 技能内 1512 个，MIT）。
- 取用：`python3 <doubao-ui-design>/scripts/icons.py find <关键词或英文名>`，输出可直接内联的 `<svg>`。
- 一稿只用一种字重；图标颜色继承 `currentColor`。
- 禁止：emoji 当图标、单个字母占位（如 "X"）、无来源手绘 path。

## 5. 改版流程

1. 弹框 / 表单 / 空状态等界面改动，先按本规范写文案与结构；
2. 需要完整界面设计交付（原型 / 设计说明）时，走 doubao-ui-design 技能主链路（brief → 做 → review → ship）；
3. 改完 build 前端并截图核对真实渲染效果，再交付。
